# 엔진 명세 초안 (첫 흐름: 프롤로그 → 캐릭터 선택 → 프로필 숙지)

2026-10-17 초안(개발 계획 0-6). **승인 전**이며 사용자가 고치면 이 문서를 고친다. 설계 결정은 `ENGINE_DESIGN.md`, 순서는 `DEVELOPMENT_PLAN.md`.
스크립트는 "파이썬 문법을 따르는 제한된 언어"의 **의사 코드**이고 확정된 문법이 아니다(이름은 한글로 적었다). 입력을 기다리는 `기다리기(...)` 는 **순서대로 읽히는 모양**으로 쓰고, 실행은 실행 상태를 데이터로 관리하는 방식(A2, `ENGINE_DESIGN.md` 1-9)이다.

## 1. 기본 개념

- **카드 실행**: 페이즈가 시작되면 그 페이즈의 카드(진행단계 배치)마다 스크립트의 `실행(카드)` 가 시작된다. 한 페이즈에 카드가 여럿이면 함께 실행된다(토론·밀담 등).
- **카드 설정**: 카드를 놓은 자리의 `진행구성.설정`(JSON)을 `카드.설정` 으로 읽는다.
- **단계 종료**: 기본은 엔진이 정한다(시간 만료, 방장의 넘기기). **스크립트도 코드로 단계를 끝낼 수 있다**(`단계_끝내기()`, 사용자 설명 2026-10-17). 스크립트가 종료를 **막는** 기능은 두지 않는다(필요하지 않음, 사용자 2026-10-17). 시간 종료 뒤의 진행 방식 기본값은 **방장이 넘기기 전에는 시간이 지나도 넘어가지 않는 것**이므로, 캐릭터를 다 못 골랐을 때 기다리는 것은 이 기본값으로 충분하다.
- **화면 요청**: 스크립트는 "누구에게 무엇을 보여 줄지"를 요청하고, 그릴 방법은 플레이 화면이 안다.
- **보는 사람**: 플레이어(인물), GM 관전, 일반 관전. 서버가 보는 사람에게 허용된 것만 내려 준다.

## 2. 첫 흐름의 스크립트 초안

### 프롤로그
```
def 실행(카드):
    모두.탭("공통 스토리", 글(공통스토리()))
    읽기(모두, 이름="공통 스토리", 내용=글(공통스토리()))
```

### 캐릭터 선택
```
def 실행(카드):
    모두.보이기(선택지(이름="캐릭터 선택", 항목=인물들(), 한사람당=1))
    모두.보이기(현황(이름="선택 완료", 완료=배정된_플레이어수(), 전체=플레이어수()))
    while 인물이 없는 플레이어가 있다():
        입력 = 기다리기(선택)                 # 누군가 하나를 고를 때까지
        if 배정(입력.플레이어, 입력.값):        # 선착순, 한 번에 하나씩 원자적으로
            모두.갱신(현황)
        else:
            입력.플레이어.알림("이미 다른 사람이 고른 인물입니다")

```

### 프로필 숙지
```
def 실행(카드):
    for 플레이어 in 플레이어들():
        번호들 = 카드.설정.공개.get(플레이어.인물, [1])        # 기본은 서사 1
        내용 = 글(서사들(플레이어.인물, 번호들))                # 고른 서사를 이어서
        플레이어.탭("개인 서사", 내용)                            # 가장 최근 카드의 선택으로 교체
        읽기(플레이어, 이름="개인 서사", 내용=내용)
```
`읽기(대상, 이름, 내용)` 는 **글 + "확인" 버튼 + 완료 현황(n/전체)** 을 묶은 것이다. 플레이어는 버튼을 눌러 완료를 표시하고, 관전자는 현황만 본다. 첫 구현에서는 엔진이 가진 하나의 묶음으로 두고, 나중에 복합 블록으로 옮길 수 있다.

## 3. 필요한 명령 (첫 흐름)

| 종류 | 명령 | 설명 |
|---|---|---|
| 읽기 | `플레이어들()`, `플레이어수()`, `인물들()`, `공통스토리()`, `서사들(인물, 번호들)`, `카드.설정` | 서사는 서버가 부분 목록으로 해석한 것(1-4-6). 비공개는 서버가 거른다 |
| 읽기 | `인물이 없는 플레이어가 있다()`, `배정된_플레이어수()` | 캐릭터 선택 상태 |
| 화면 | `대상.보이기(블록)`, `대상.탭(이름, 내용)`, `대상.알림(글)`, `모두.갱신(블록)` | 대상은 `모두` 또는 한 명 |
| 묶음 | `읽기(대상, 이름, 내용)` | 글 + 완료 버튼 + 현황 |
| 입력 | `기다리기(선택)` | 입력은 `{질문ID, 플레이어, 값}`. 질문마다 고유 ID |
| 변경 | `배정(플레이어, 인물)` | 선착순. 성공/실패를 돌려준다. 같은 인물은 한 사람만(DB 의 `참여(진행, 인물)` 유일 제약으로도 보장) |

## 4. 필요한 화면 블록 (첫 흐름)

`글`, `선택지`(항목, 한 사람당 몇 개), `버튼`(완료), `현황`(완료 수 / 전체), `탭`.

## 5. 엔진 ↔ 화면의 약속

- **상태 조회**: 현재 페이즈, 서버 기준 시각과 종료 예정 시각, 일시정지 여부, 진행 권한 여부, 내 인물, 화면 블록들, 탭들, 대기 중인 질문 ID. 모두 **보는 사람에게 허용된 범위**로 만들고 **버전 번호**를 붙인다.
- **행동 제출**: `{질문ID, 값}` 을 일반 요청으로 보낸다. 질문 ID 가 맞지 않거나 이미 처리된 것은 걸러 낸다.
- **알림(SSE)**: "버전이 바뀌었다"만 알린다. 화면은 상태를 다시 조회한다(`ENGINE_DESIGN.md` 1-8).
- **엔진 상태**(첫 구현): 현재 페이즈와 카드 실행 상태(위치, 변수, 기다리는 질문), 페이즈 시작·종료 시각, 일시정지, 진행 권한자, 상태 버전은 메모리에, 배정(`참여.인물_순서`)과 같은 기록은 DB 에 둔다.

## 6. 확인이 필요한 것

결정된 것(사용자 2026-10-17): 전원이 "확인"을 눌러도 **전원 완료만 표시**하고 단계는 저절로 끝나지 않는다. 캐릭터 선택을 바꾸거나 "확인"을 취소하는 기능은 없다. 공통 스토리 탭은 기본적으로 모든 단계에서 남는다. 스크립트는 코드로 단계를 끝낼 수 있고, 종료를 막는 기능은 없다. 시간 종료 뒤에도 방장이 넘기기 전에는 넘어가지 않는 것이 기본이다.

남은 것:
1. **방장이 캐릭터를 다 고르기 전에 넘기려 하면 "캐릭터 선택이 완료되지 않았습니다."라는 안내를 보여 준다**(사용자 2026-10-17). 안내만 보여 주고 넘어가는지(경고), 안내를 보여 주고 넘기지 않는지(막기)는 확인 필요. 막기라면 앞에서 뺀 "종료를 거부하는 기능"이 방장의 넘기기에 한해 다시 필요하고, "방장은 언제든 먼저 진행할 수 있다"는 결정과 부딪힌다. 경고라면 인물이 없는 플레이어가 생길 수 있으므로 그런 플레이어에게 인물이 필요한 화면을 보여 주지 않는 것을 안전한 기본 동작으로 둔다.
2. 이 초안(명령 목록, 블록 목록, 화면과 엔진의 약속)의 승인.
