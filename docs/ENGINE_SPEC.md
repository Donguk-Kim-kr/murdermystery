# 엔진 명세 (첫 흐름: 프롤로그 → 캐릭터 선택 → 프로필 숙지)

2026-10-17 작성(개발 계획 0-6). **사용자가 승인함(2026-10-17).** 구현 중에 틀린 곳이 드러나면 이 문서를 고치고 다시 확인을 받는다. 설계 결정은 `ENGINE_DESIGN.md`, 순서는 `DEVELOPMENT_PLAN.md`.
스크립트는 "파이썬 문법을 따르는 제한된 언어"이다. 아래 예는 **구현된 문법**(2단계, `backend/app/script`, `backend/app/cards.py`)으로 적었고, 이름은 한글이며 공백 없이 밑줄을 쓴다. 입력을 기다리는 `기다리기(...)` 는 **순서대로 읽히는 모양**으로 쓰고, 실행은 실행 상태를 데이터로 관리하는 방식(A2, `ENGINE_DESIGN.md` 1-9)이다.

## 1. 기본 개념

- **카드 실행**: 페이즈가 시작되면 그 페이즈의 카드(진행단계 배치)마다 스크립트의 `실행(카드)` 가 시작된다. 한 페이즈에 카드가 여럿이면 함께 실행된다(토론·밀담 등).
- **카드 설정**: 카드를 놓은 자리의 `진행구성.설정`(JSON)을 `카드.설정` 으로 읽는다.
- **단계 종료**: 기본은 엔진이 정한다(시간 만료, 방장의 넘기기). **스크립트도 코드로 단계를 끝낼 수 있다**(`단계_끝내기()`, 사용자 설명 2026-10-17). 시간 종료 뒤의 진행 방식 기본값은 **방장이 넘기기 전에는 시간이 지나도 넘어가지 않는 것**이다. 카드는 **다음 단계로 진행하기 위한 최소 조건**(`진행조건`)을 걸 수 있고, 조건이 맞지 않으면 안내 메시지를 보여 주고 넘어가지 않는다. 이것은 방장의 권한을 막는 것이 아니라 게임이 진행되려면 필요한 최소 조건이며, **기본 진행단계 중에서는 캐릭터 선택 카드만** 건다(사용자 2026-10-17).
- **탭 유지**: 공통 스토리(프롤로그), 자기소개, 개인 서사처럼 계속 읽을 수 있어야 하는 탭은 **카드 설정 `내용유지`(기본 남김)** 으로 정한다. 남기면 그 탭은 **이후 모든 단계에서 계속 보인다**(같은 이름의 탭을 나중 카드가 다시 정하면 교체된다). 제작자가 카드를 놓을 때 고른다. 제작 화면에서의 이름은 **"내용 유지"** 이다(사용자 2026-10-17, 설정 키도 `내용유지`, 상세 설명 글은 지금은 두지 않는다).
- **화면 요청**: 스크립트는 "누구에게 무엇을 보여 줄지"를 요청하고, 그릴 방법은 플레이 화면이 안다.
- **보는 사람**: 플레이어(인물), GM 관전, 일반 관전. 서버가 보는 사람에게 허용된 것만 내려 준다.

## 2. 첫 흐름의 스크립트 초안

### 프롤로그
```
def 실행(카드):
    모두.탭("공통 스토리", 글("공통 스토리", 공통스토리()))
    읽기(모두, "공통 스토리", 공통스토리())
```

### 캐릭터 선택
캐릭터를 **클릭하는 것은 고르는 것일 뿐 확인이 아니다.** 클릭한 뒤 **"확인"을 눌러야 확정**되고, 확인한 뒤에는 되돌릴 수 없다(확인 전에는 다른 인물을 클릭해 바꿀 수 있는 것으로 이해, 사용자 2026-10-17). 클릭은 화면에만 있고 서버에는 "확인"이 올 때 `{질문ID, 고른 인물}` 이 간다.
```
def 실행(카드):
    모두.보이기(선택지("캐릭터 선택", 인물들(), 1, True))
    모두.보이기(현황("선택 완료", 배정된_플레이어수(), 플레이어수()))
    while 인물_없는_플레이어가_있다():
        입력 = 기다리기("확인")                # 인물을 클릭한 뒤 "확인"을 누를 때까지
        if 배정(입력.플레이어, 입력.값):          # 선착순, 한 번에 하나씩 원자적으로. 확인한 뒤에는 되돌릴 수 없다
            모두.보이기(현황("선택 완료", 배정된_플레이어수(), 플레이어수()))     # 같은 이름의 블록은 교체된다
        else:
            입력.플레이어.알림("이미 다른 사람이 고른 인물입니다")

def 진행조건(카드):
    if 인물_없는_플레이어가_있다():
        return 거부("캐릭터 선택이 완료되지 않았습니다.")
    return 통과
```

### 프로필 숙지
```
def 실행(카드):
    공개 = 카드.설정.get("개인서사공개", {})
    for 플레이어 in 플레이어들():
        if 플레이어.인물 is None:
            continue
        번호들 = 공개.get(str(플레이어.인물.순서), [1])          # 설정의 키는 인물의 순서(문자열). 기본은 서사 1
        내용 = 서사들(플레이어.인물, 번호들)                      # 고른 서사를 이어서
        플레이어.탭("개인 서사", 글("개인 서사", 내용))            # 가장 최근 카드의 선택으로 교체
        읽기(플레이어, "개인 서사", 내용)
```
`읽기(대상, 이름, 내용)` 는 **글 + "확인" 버튼 + 완료 현황(n/전체)** 을 묶은 것이다. 플레이어는 버튼을 눌러 완료를 표시하고, 관전자는 현황만 본다. 첫 구현에서는 엔진이 가진 하나의 묶음으로 두고, 나중에 복합 블록으로 옮길 수 있다.

## 3. 필요한 명령 (첫 흐름)

| 종류 | 명령 | 설명 |
|---|---|---|
| 읽기 | `플레이어들()`, `플레이어수()`, `인물들()`, `공통스토리()`, `서사들(인물, 번호들)`, `카드.설정` | 서사는 서버가 부분 목록으로 해석한 것(1-4-6). 비공개는 서버가 거른다 |
| 읽기 | `장소들()`(가장 안쪽 장소), `보유목록(플레이어)`(얻은 단서·증언 `{종류, 이름, 내용, 장소}`) | 조사 단계 |
| 읽기 | `인물_없는_플레이어가_있다()`, `배정된_플레이어수()` | 캐릭터 선택 상태 |
| 블록 | `글(이름, 내용)`, `선택지(이름, 항목, 한사람당, 확인필요)`, `입력(이름, 질문, 글자수)`(글자를 받는다. 답은 `기다리기(이름)`), `현황(이름, 완료, 전체)`, `카드목록(이름, 항목, 동작)`(단서·증언 카드를 앞면이 보이게 늘어놓는다. `동작`에 "보여주기"·"양도"를 주면 카드마다 버튼이 생기고, 누르면 `기다리기(이름)` 이 `{플레이어, 값: {동작, 단서, 대상}}` 을 돌려준다. 값의 모양은 서버가 검사한다) | 같은 이름의 블록은 나중 것이 대신한다. 나에게만 보이도록 한 것은 모두에게 보이는 같은 이름의 블록을 대신한다 |
| 읽기 | `받은공개(플레이어)` | 다른 사람이 이 플레이어에게(또는 전체에게) 보여 준 단서 `{종류, 이름, 공개이름, 내용, 장소, 주인}` |
| 읽기 | `모든_장소()`, `단서들()` | 바깥 장소를 포함한 모든 장소, 작품의 모든 단서(증언 제외). 투표칸의 후보로 쓰면 화면에는 장소 경로와 단서의 공개이름이 보인다 |
| 읽기 | `인물찾기(순서)`, `투표수(이름)`, `최다득표(이름)`, `결과(이름)` | `인물찾기`: 순서 번호로 인물을 찾는다(NPC 포함, 없으면 `None`). `기타후보(값)`: 인물이 아닌 투표 선택지로 쓸 수 있는 글이면 그 글, 아니면 `None`. `후보값(후보)`: 후보의 값(인물이면 순서 번호, 글이면 그 글). `투표수`: 투표한 사람 수. `최다득표`: 가장 많은 표를 받은 인물들(동률이면 여럿). `결과`: 유일한 최다 득표 후보(인물이면 인물, 사고사 같은 선택지이면 그 글), 동률이거나 투표가 없으면 `None`(구속 없음). `결과_인물`·`결과_기타` 는 그 종류일 때만 값을 돌려준다 — 엔딩 조건이 이것을 읽는다 |
| 블록 | `투표칸(이름, 후보, 질문)` | 비공개 투표 칸. 후보는 인물이나 인물이 아닌 선택지(글, 예: "사고사")의 목록이다. 플레이어는 다음 단계로 가기 전까지 다시 골라 바꿀 수 있고 자기 인물은 고를 수 없다. 투표하면 `기다리기(이름)` 이 `{플레이어, 값: 인물 순서}` 를 돌려준다. 남의 표는 어디에도 내려가지 않는다 |
| 엔진 | `투표(이름, 플레이어, 인물)`, `투표초기화(이름)` | 표를 기록(이미 했으면 바꿈, 없는 인물이거나 자기 인물이면 False)하고, 재투표를 시작할 때 표를 모두 지운다 |
| 읽기 | `질문정의(값)` | 카드 설정에 적은 질문을 `{질문, 선택, 글자수}` 로 정리한다(글자만 적으면 글로 답하는 질문, `{"질문", "선택"}` 이면 고르는 질문). 읽을 수 없으면 `None` |
| 읽기 | `변수(이름, 기본값)`, `가지고_있다(플레이어, 단서이름)`, `단서_보유자(단서이름)`(단서이름은 **진짜 이름**(`이름`)과 맞춘다. 공개이름으로는 찾지 않는다), `인물의_플레이어(인물)` | 엔딩·후일담의 조건이 읽는 상태. 변수는 스크립트가 `변수설정` 으로 남긴다 |
| 엔진 | `변수설정(이름, 값)` | 게임 변수를 정한다(글자·숫자·참/거짓·목록·사전, 값 하나 2000자 이하, 500개까지). "인물 B 가 비밀을 알아챘다", 능력을 쓴 결과 같은 것을 기록해 두면 엔딩 조건이 읽는다 |
| 읽기 | `엔딩분기들()`, `후일담들()`, `조건_맞음(항목)` | 엔딩 분기·후일담 목록과 그 조건이 지금 맞는지. 항목에는 `.이름`, `.내용`, `.순서`(후일담은 `.인물`) 가 있다 |
| 읽기 | `모든_단서()`, `모든_인물()`, `서사_전체(인물)` | 전체 공개 단계용 |
| 엔진 | `양도(플레이어, 받는사람, 단서)` | 단서를 받는 사람에게 **바로** 넘긴다(수락 없음). 성공하면 True. 그 단서에 걸린 공개는 모두 사라진다. 증언은 안 된다 |
| 엔진 | `공개설정(플레이어, 단서, 대상)` | 단서를 볼 수 있는 사람을 바꾸어 놓는다. 대상은 `"전체"` 이거나 플레이어(계정 번호) 목록이고, 빈 목록이면 공개를 모두 취소한다 |
| 엔진 | `조사(플레이어, 장소)` | 장소에서 항목 하나를 얻어 `{종류, 이름, 공개이름, 내용, 장소}` 를 돌려준다(`이름` 은 진짜 이름, `공개이름` 은 남들에게 보이는 이름이며 비워 두었으면 진짜 이름과 같다. 조사 결과를 따로 보여 주지 않으므로 기본 조사 카드는 얻은 것을 내 단서 탭에 쌓기만 한다)(없거나 장소가 아니면 `None`). 단서가 먼저, 남은 단서가 없으면 아직 얻지 못한 증언. 장소를 `선택지(이름, 장소들(), 1, False)` 로 보이면 얻을 것이 없는 장소는 그 플레이어에게 비활성으로 보인다 |
| 화면 | `대상.보이기(블록)`, `대상.탭(이름, 내용)`, `대상.알림(글)` | 대상은 `모두` 또는 한 명 |
| 묶음 | `읽기(대상, 이름, 내용)` | 글 + 완료 버튼 + 현황 |
| 입력 | `기다리기(확인)` | 입력은 `{질문ID, 플레이어, 값}`(값은 클릭해서 고른 것). 질문마다 고유 ID |
| 변경 | `배정(플레이어, 인물)` | 선착순. 성공/실패를 돌려준다. 같은 인물은 한 사람만(DB 의 `참여(진행, 인물)` 유일 제약으로도 보장) |
| 진행조건 | 핸들러 `진행조건(카드)` → `통과` / `거부(메시지)` | 다음 단계로 넘어가려 할 때(시간 만료, 방장의 넘기기) 엔진이 묻는다. 정의하지 않은 카드는 `통과` |

## 4. 필요한 화면 블록 (첫 흐름)

`글`, `선택지`(항목, 한 사람당 몇 개, `확인필요` 이면 "확인" 버튼을 함께 보여 준다), `버튼`(완료), `현황`(완료 수 / 전체), `탭`.

## 5. 엔진 ↔ 화면의 약속

- **상태 조회**: 현재 페이즈, 서버 기준 시각과 종료 예정 시각, 일시정지 여부, 진행 권한 여부, 내 인물, 화면 블록들, 탭들, 대기 중인 질문 ID. 모두 **보는 사람에게 허용된 범위**로 만들고 **버전 번호**를 붙인다.
- **행동 제출**: `{질문ID, 값}` 을 일반 요청으로 보낸다. 질문 ID 가 맞지 않거나 이미 처리된 것은 걸러 낸다.
- **알림(SSE)**: "버전이 바뀌었다"만 알린다. 화면은 상태를 다시 조회한다(`ENGINE_DESIGN.md` 1-8).
- **엔진 상태**(첫 구현): 현재 페이즈와 카드 실행 상태(위치, 변수, 기다리는 질문), 페이즈 시작·종료 시각, 일시정지, 진행 권한자, 상태 버전은 메모리에, 배정(`참여.인물_순서`)과 같은 기록은 DB 에 둔다.

## 6. 확인이 필요한 것

## 8. 엔딩·후일담의 조건 (사용자 2026-10-18)

- (제작 화면에서는 식을 쓰지 않는다. 아래 10 참고. 이 절은 저장되는 모양과 식의 규칙이다.) 엔딩 분기와 후일담의 `조건` 은 `{"식": "조건 식"}` 으로 저장한다. 식은 스크립트와 같은 언어의 식 하나이고 **읽기만** 한다(상태를 바꾸는 함수는 쓸 수 없다). 비어 있으면(`{}` 또는 비움) 항상 적용된다. 확정할 때 문법·이름을 검사한다(오류는 확정을 막는다).
- 예: **투표로 범인을 검거했다** → `결과_인물("최종 투표") is not None and 결과_인물("최종 투표").범인` (인물 화면에서 범인으로 표시한 인물이 최다 득표를 받았을 때. 범인이 여럿이면 그중 누구든 맞는다. 동률이거나 사고사 같은 선택지가 최다 득표이면 거짓), "검거 실패"를 `not (…)` 로 쓰면 **동률·투표 없음까지 실패로 잡힌다**. 나누어 쓰려면 동률 `len(최다득표("최종 투표")) > 1`, 투표 없음 `투표수("최종 투표") == 0`, 검거 실패 `결과("최종 투표") is not None and not (결과_인물("최종 투표") is not None and 결과_인물("최종 투표").범인)` (최다 득표가 범인이 아닌 인물이거나 사고사 같은 선택지) 로 쓴다.
- 예: 최종 투표 A 구속 → `결과_인물("최종 투표") is not None and 결과_인물("최종 투표").이름 == "A"`, 구속 실패 → `결과_인물("최종 투표") is None or 결과_인물("최종 투표").이름 != "A"`, B 가 비밀을 알아챔 → `변수("B 비밀 인지") == True`, 사고사에 가장 많은 표 → `결과_기타("최종 투표") == "사고사"`.
- **여러 분기의 조건이 동시에 맞으면 맞는 것을 모두 분기 순서대로 보여 준다**(제작자가 서로 겹치지 않게 조건을 쓰면 하나만 보인다). 맞는 것이 없으면 아무것도 보이지 않는다(조건이 빈 분기를 "기본 엔딩"으로 두면 항상 보인다). 구현하면서 정한 규칙이며 사용자 확인 전이다.
- 인물별 능력의 사용 결과처럼 게임 중에 일어난 일은 스크립트(나중에는 기믹)가 `변수설정` 으로 남기고 조건이 `변수(...)` 로 읽는다. 능력 자체를 만드는 방법(기믹)은 단계 7에서 만든다.

## 8-1. 능력 사용 (사용자 2026-10-18)

- 능력은 **기본적으로 대상을 지목하는 것**이고, 대상은 **인물·장소·단서** 중에서 고른다. 기본 진행단계 "능력 사용" 이 이를 맡는다(`default_phases.py` `ABILITY`). 능력은 인물 화면의 `능력` 글이 있는 인물의 플레이어만 쓴다.
- 카드 설정 `대상`(인물/장소/단서, 기본 인물)으로 후보 종류를 정한다. "사용 안 함" 은 언제나 후보에 있다. 각자 자기 능력만 보고, 누가 누구를 골랐는지는 보이지 않으며 몇 명이 썼는지만 보인다. 넘어가기 전에는 바꿀 수 있다. 자기 인물은 고를 수 없다.
- 지목은 게임 변수 `"<이름>:<인물 순서>"`(이름은 설정 `이름`, 기본 "능력 사용")에 남는다. 값은 인물이면 순서 번호, 장소·단서이면 `"장소:2"`·`"단서:3"`, 쓰지 않으면 `"사용 안 함"`. 엔딩·후일담의 조건이 `변수("능력 사용:1") == "장소:2"` 처럼 읽는다.
- 단서 후보는 공개이름으로 보이며, 작품의 모든 단서가 후보이다(제 판단, 확인 전).
- **전체 시나리오 중 원할 때 쓰는 능력**은 기믹으로 만든다(단계 7). 지금은 "능력 사용" 단계를 흐름에 놓는 방식만 있다.

## 9. 개인 질문 (사용자 2026-10-18)

투표 뒤에도 **인물마다 자기 질문에 답해야 하는 경우**가 있다. 기본 진행단계 "개인 질문" 이 이를 맡는다(`default_phases.py` `PERSONAL_QUESTION`).
- 카드 설정 `질문`: `{"인물 순서": "질문 글"}` 또는 `{"인물 순서": {"질문": "…", "선택": ["예", "아니오"], "글자수": 300}}`. 선택이 있으면 고르는 질문이고 없으면 글로 답한다. 질문이 없는 인물은 "답할 질문이 없다"는 안내만 본다. 설정 화면에서 인물마다 질문과 선택지를 만든다(선택지는 하나씩 추가·삭제하므로 쉼표가 들어가도 된다).
- 각자 자기 질문만 보고 답은 비공개이며, **몇 명이 답했는지만** 모두에게 보인다. 다음 단계로 넘어가기 전에는 답을 바꿀 수 있다. 답은 게임 변수 `"<이름>:<인물 순서>"`(이름은 설정 `이름`, 기본 "개인 질문")에 남고 엔딩·후일담의 조건이 `변수("개인 질문:2") == "예"` 처럼 읽는다. 질문 카드를 여러 번 놓으면 `이름` 을 다르게 한다.
- `기다리기("확인", 이름)` 처럼 **여러 종류를 한꺼번에 기다릴 수 있다**(고르는 질문과 글로 답하는 질문이 한 카드에 섞이므로).

## 10. 진행단계가 스스로 정하는 제작 화면 (사용자 2026-10-18)

- **원칙**: 식(조건식·스크립트)은 진행단계와 기믹을 만드는 쪽에만 있다. 작품 제작자는 식을 쓰지 않고 입력칸·선택지·버튼(드롭다운)으로만 고른다.
- 진행단계 스크립트가 두 함수로 그 화면을 정한다. 서버가 이 두 함수만 안전하게 돌려서(게임은 돌리지 않는다, `app/declare.py`) 제작 화면에 내려 준다. 규칙(JSONB)에는 지금처럼 스크립트만 저장된다. 두 함수가 모두 없으면 옛 방식(스크립트가 글자로 가리키는 설정 이름만 전용 입력으로 보인다)이다.
- `설정정의(카드)` → 흐름 카드 설정 화면의 입력칸 목록. 칸을 만드는 함수: `숫자칸(키, 이름, 기본, 최소=0, 설명="")`, `선택칸(키, 이름, 선택지, 기본=None, 설명="")`(선택지는 글 또는 [값, 표시]), `켜짐칸(키, 이름, 기본=True, 설명="")`, `글칸(키, 이름, 기본="", 설명="")`, `여러선택칸(키, 이름, 선택지, 기본, 설명="")`, 그리고 전용 입력이 있는 `서사칸()`(개인서사공개), `후보칸()`(투표 후보), `질문칸()`(개인 질문). 값이 기본과 같으면 저장하지 않는다.
- `조건정의(카드)` → 엔딩·후일담의 조건으로 고를 수 있는 항목 목록. `조건항목(이름, 식, 인자=[…])`. 식 안의 `{키}` 는 고른 값(숫자나 따옴표 글), `{키:글}` 은 따옴표 없는 글, `{@설정키}` 는 이 카드의 설정 값(없으면 기본값)으로 바뀐다. 인자 칸: `인물칸`, `값선택칸`, `기타후보칸`(카드 설정 `후보` 의 글 후보), `질문인물칸`·`질문답칸`(카드 설정 `질문`), `대상칸`(능력 지목 대상, 카드 설정 `대상`).
- 결말 탭의 엔딩 분기·후일담은 흐름에 놓인 카드가 내놓은 조건 항목을 **고르고 빈칸을 채운다**. 여러 개를 고르면 모두 맞아야 한다(그리고). 저장은 `{"식": "(…) and (…)", "구성": [{카드, 조건, 인자}]}` 이고 서버는 식만 검사한다(확정 때 문법·이름 검사). 식으로만 저장된 옛 조건은 "코드로 쓴 조건"으로 보이고 지울 수 있다.
- "또는"·"아니다"가 필요하면 조건 항목을 만드는 쪽이 식 안에서 처리해 하나의 항목으로 내놓는다.
- 저장할 때 검사: 진행단계를 라이브러리에 저장할 때와 스크립트 검사 API가 두 함수를 돌려서 오류(키 겹침, 식의 자리표시자에 맞는 인자 없음 등)를 알린다.
- 기본 진행단계의 선언: 프로필 숙지(서사), 조사(횟수), 토론(보여주기·양도 허용), 밀담·추리 발표·전체 공개(안내), 최종 투표(후보·동률·재투표 + 조건: 범인 검거, 검거 실패, 동률, 투표 없음, 특정 인물, 인물이 아닌 후보), 개인 질문(질문·이름 + 조건: 이 인물이 이렇게 답했다), 능력 사용(대상·이름 + 조건: 이 대상에게 썼다, 쓰지 않았다, 썼다).
