# 개발 계획 (플레이 기능)

2026-10-17 작성. 제작 쪽(계정, 작품, 콘텐츠 편집, 흐름 화면, 확정·버전, 방 만들기·입장·대기실)은 만들어져 있고,
이 계획은 **게임을 실제로 진행하는 부분**(엔진, 해석기, 플레이 화면, 제작 도구 연결)을 만든다.
설계 결정은 `ENGINE_DESIGN.md`, `EDITOR_DESIGN.md`, `DB_RULES.md` 에 있다.

## 진행 원칙

1. **얇게 끝까지**: 부분을 따로 완성하지 않고, 작은 흐름 하나가 엔진 → 해석기 → 플레이 화면 → 제작 도구를 모두 통과하게 만든 뒤 넓힌다.
2. **하나가 끝나야 다음으로 간다.** 각 단계에는 완료 기준이 있고, 기준을 통과하기 전에는 넘어가지 않는다.
3. **결정이 필요하면 멈추고 사용자에게 묻는다.** 추측으로 채우지 않는다. 결정은 그 자리에서 문서에 기록한다.
4. **단계가 끝날 때마다** 테스트를 통과시키고 문서를 고친 뒤 커밋·푸시한다.
5. **설계가 틀렸다고 드러나면** 앞 단계로 돌아가 고치고, 무엇이 왜 바뀌었는지 문서에 남긴다.
6. 소요 시간은 예측하지 않는다(근거가 없다).

## 현재 상태

- 있음: 계정·작품·인물·장소·단서 등 제작 콘텐츠, 진행단계·기믹 라이브러리, 흐름 편집(페이즈·카드·카드 설정 JSON), 확정(스냅샷·버전), 방 만들기·입장·대기실,
  게임 실행용 테이블(`방`, `진행`, `참여`, `기믹실행`, `투표결과`, `엔딩`, `획득`).
- 없음: 게임 진행 엔진, 해석기, 플레이 화면(대기실 이후), 서사 분할 입력, `인물.소개`, 실시간 연결.

## 시험 작품

플랫폼 검증용 작품으로, 내용은 아무 글이어도 된다(재미나 추리는 상관없다). 사용자가 제작기로 흐름(껍데기)을 만들고, 제작기에 아직 없는 부분(공통 스토리·서사 나누기·카드 설정)은 단계 4에서 채운다.

- 전체 흐름(사용자 결정 2026-10-17): 프롤로그 → 캐릭터 선택 → 프로필 숙지 → 자기소개 → 조사 → **토론·밀담**(한 페이즈에 두 카드) → 추리 발표 → 최종 투표 → **엔딩** → 후일담 → 전체공개.
- 구현은 이 중 앞의 세 단계(첫 흐름)부터 하고, 나머지는 단계 6에서 채운다.

## 단계 2. 해석기 최소판

목표: 첫 흐름 세 진행단계를 **스크립트로** 실행한다(고정 코드가 아니다).

- 문법: 파이썬 문법 중 허용한 것만(`ast` 로 읽어 허용 목록만 통과, `exec`/`eval` 사용 안 함).
- 엔진 명령 호출, 이벤트 처리, **입력을 기다렸다 이어서 실행**, 시간 종료·연결 끊김 때의 처리.
- 저장할 때 검사: 문법 오류, 없는 명령·이름 참조, 오류 메시지.

완료 기준: 단계 1의 시험을 스크립트로 되풀이해도 같은 결과. 허용되지 않은 코드가 실행되지 않는 시험 포함.

## 단계 3. 플레이 화면 최소판

목표: 여러 브라우저에서 서로 다른 플레이어가 첫 흐름을 진행한다.

- 기본 블록: 글, 선택지 목록, 버튼, 탭(공통 스토리·개인 서사). 서버의 화면 요청을 그리는 공통 렌더러.
- 입력을 서버로 전달, 실시간 수신, 재접속 처리.
- 대기실 → 시작 → 첫 흐름 진행.

완료 기준: 브라우저 여러 개(자동화 시험 포함)에서 같은 캐릭터를 동시에 골랐을 때 한 명만 성공, 개인 서사가 본인에게만 보임, 새로고침 후 복원. 사용자가 직접 여러 창으로 플레이해 확인.

## 단계 4. 제작 도구 연결

목표: 첫 흐름을 **제작 화면에서 만들어서** 플레이한다.

- 진행단계 스크립트 편집(검사·오류 안내, 최소 시험 실행).
- 프로필 숙지 카드 설정 화면(캐릭터별 보여 줄 서사), 서사 "추가하기" 입력, `인물.소개` 컬럼.
- 확정 스냅샷에 필요한 내용(서사 부분 목록 등) 포함.

완료 기준: 새 작품을 제작 화면만으로 만들고 확정해서 방을 열고 첫 흐름을 끝까지 플레이한다.

## 단계 5. 일반성 점검 (쏠림 확인)

목표: 첫 흐름에 맞춰 부품이 굳어지지 않았는지 확인한다.

- 기본 11개에 없는 모양의 진행단계(예: 모두가 동시에 답하고 한꺼번에 공개) 하나를 같은 부품으로 만든다.
- 막히는 부분은 명령 목록과 기본 블록의 세밀함 결정에 반영한다(예: 이미지 위 클릭 같은 재료가 필요한가).

완료 기준: 두 번째 흐름이 부품 추가를 최소로 하고 돌아간다. 막힌 지점이 문서에 기록된다.

## 단계 6. 나머지 기본 진행단계

각 진행단계마다 같은 순서로 한다: 설정 구조 → 엔진 명령 → 스크립트 → 화면 블록 → 제작 편집 → 테스트.
제안 순서(앞의 것이 뒤의 것에 필요한 부품을 먼저 만든다):

1. 자기소개(`인물.소개` 표시)
2. 조사(선착순 / 동시 1개씩과 횟수, 안내 문구, 단서 획득 `획득`)
3. 토론(단서 보여 주기·양도)
4. 밀담(안내 문구만)
5. 추리 발표(발표 시간)
6. 최종 투표(1표 비공개 동시 투표, 자기 투표 금지, 동률 규칙: 재투표/구속 없음, 한도 없음 포함)
7. 엔딩(엔딩 분기 조건, 옛 이름 에필로그)
8. 후일담(적용 조건에 따라 인물마다)
9. 전체 공개(종료 안내, 모든 단서·모든 인물 서사)

같은 단계에서 **시간 제어**도 만든다: 자동 진행 / 방장 진행(방장이 플레이 화면에서 방마다 고름), 일시정지, 방장의 조기 진행.

각 진행단계의 완료 기준: 자동 테스트 + 여러 브라우저 시나리오 통과. 진행단계마다 "확인 필요"로 남은 항목을 시작 전에 사용자에게 묻는다.
